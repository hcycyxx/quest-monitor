# 任务悬浮窗 V5 · DSH 接入说明

原路径 `ui/quest_window.py` 已更新，仍可直接 `python quest_window.py` 运行。
单文件，仅 Python 标准库与 tkinter，无需安装依赖。

## 本次视觉交付

- 顶部四色按钮：深蓝玻璃、轻透悬浮、杂志手账、夜航 HUD。皮肤仅在本次运行中保留，不写任务 JSON。
- 默认当前行动＋进度环；点击行动区展开。主线、支线各自可折叠。
- 每项任务有短进展及进度条。标题切完成、步骤勾选、全部勾选自动完成、ⓘ 说明保持可用。
- 勾选：冰蓝扩散光圈；整项完成：少量蓝/金/绿烟花粒子，约 0.58 秒结束。
- 顶部拖动；左右吸附后，移开约 0.75 秒缩成把手。移入展开；把手点击可固定，展开后顶部圆针按钮可取消固定。展开过渡期间的点击不会误触关闭。
- 最小化窄条、关闭、已完成折叠、完成时间轴、今日回顾。长列表有滚轮和细滚动条。
- 轻透悬浮采用 Tk 整体 90% 透明，文字也一起透明；玻璃版为分层色面与高光模拟，不是真实背景模糊。

## 不变的接口

已通过 AST 比较，以下实现与原版一致：

`ROOT`、`STATE_FILE`、`load_state()`、`save_state()`、`_toggle_step()`、`_toggle_quest()`、`_snap_edge()`、`tick()`。

`tick()` 仍每 3 秒检查文件变化。所有任务写入仍由原版两个切换方法调用原版读写函数。
未修改 engine、config 或真实任务 JSON；原有两个进程同时读写的机制也没有改动。

`_show_tip()` 保留悬浮显示 note 的行为：修正原来的无效 `300x?` 尺寸，跟随皮肤配色，并避免提示跑出屏幕。

## 数据边界与待接入功能

1. 现有 `progress` 文本可作为短进展；也能读取任务级 `live_progress` 或 `progress_summary`。
2. 进度优先读取 `progress_percent` / `estimated_progress`，范围 0–100；未完成状态最多显示估算 95%。其次读取 `progress` 百分比、勾选步骤比例或 `2/3`。步骤比例明确标为“步骤”，不是工作量估算。无依据显示“待估算”。
3. 当前引擎没有输出独立的实时进度和自动工作量估算字段；UI 不把停留时间伪装成完成度。请由引擎补充这些数据，再做实际验收。
4. UI 可只读展示 `status: waiting`，但不新增状态写入入口。锁定任务、等待状态的实际引擎控制仍待 DSH 实现。
5. 时间轴读取 `completed_at` / `completedAt` / `done_at`，以北京时间分组。旧任务没有完成时间时显示“时间未记录”，不会使用全局 `updated_at` 冒充完成时间。
6. 本窗口里手动完成的任务，在内存中记录准确点击完成时刻，可进入本次会话的时间轴与今日回顾；这个缓存不写 JSON，重启会丢失。永久历史需要引擎保存任务级完成时间。
7. 已完成任务点击恢复，严格沿用原版 `_toggle_quest()` 的语义（恢复 active 时不会自动清空旧勾选）。
